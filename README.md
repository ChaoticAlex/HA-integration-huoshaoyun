# 火烧云 / 朝霞晚霞预报 —— Home Assistant 集成

自带调度、不依赖任何外部服务；同时计算朝霞与晚霞的霞光程度（数值越高越鲜艳）。
纯数值输出，不做评级。

> ⚠️ 这是**集成（integration）**，不是加载项（addon）。装好后出现在
> 「设置 → 设备与服务 → 添加集成」。

## 安装

**HACS（推荐）**：HACS → 集成 → 右上角 ⋮ → 自定义仓库 → 填 `https://github.com/ChaoticAlex/HA-integration-huoshaoyun`
→ 类别选「集成」→ 安装 → 重启 HA → 添加集成「火烧云 / 朝霞晚霞预报」。

**手动**：把 `custom_components/huoshaoyun/` 拷进 HA 的 `custom_components/`，重启。

**地点三选一**：HA 家庭位置 / `zone` 实体 / 手动经纬度。代码内零硬编码坐标，
之后可在集成选项里改（模式、刷新间隔、云量口径、时区）。

## 实体（每个地点 6 个）

| 实体 | state | 说明 |
|---|---|---|
| `今日朝霞指数` `今日晚霞指数` `明日朝霞指数` `明日晚霞指数` | 指数 **0~2.5** | 复合指数，非物理量测量；0 = 没有可见亮面云 |
| `下次霞光气溶胶` | CAMS AOD 数值 | **该次霞光**光路的预报值，**非实时** |
| `下次霞光云层` | `none` / `low` / `mid` / `high` / `low+mid` | **该次霞光**时刻的云层结构预报，**非实时** |

事件属性：`事件时间` `距今小时`（负值=已过）`已过` `太阳方位角` `峰值` `峰值时刻`
`冻结于`（非空=事件已过、数值已冻结在最后一次事前预报，避免被事后起报改写）
`有效时段` `持续分钟` `气溶胶光学厚度` `云层` `云量来源` `各模式数值` `时间序列`
`数据指纹` `数据变更` `数据完整` `缺失数据` `口径`

云况属性（schema 稳定，缺失为 `null`）：`主导云层` `主导云底_m`
`低云_云量/云底_m/云顶_m/温度_C/相态`、`中云_*`、`高云_*`、`各事件标记` `文字描述`

## 数据与请求

- 云况 NCEP-GFS 0.25° / ECMWF-IFS 0.25°，气溶胶 CAMS，经 Open-Meteo 取数（**免 API key**）
- 每次刷新 **3 个请求**（18 个断面点 × 2 模型合并进单次请求：地表 1 + 气压层 1 + AOD 1）
- **恒定节拍**：默认 **180 分钟**一拉（可在选项里改 30~720 分钟），不做"临近事件提速"。
  模型数据只在起报更新时变化，同一份起报内分数是常数，故恒定低频就够了：

| 刷新间隔 | 轮/天 | 请求/天/地点 |
|---|---|---|
| **180 min（默认）** | 8 | **24** |
| 360 min | 4 | 12 |
| 720 min | 2 | 6 |

  对比：v1.0.x 是 5 请求/轮 + 临近提速（15 min）≈ 200 请求/天；静默期数据未变时还会复用上轮结果、跳过评分计算。

### 配额与限流

Open-Meteo 免费额度**按出口 IP** 计：**< 10000 次/天、5000 次/小时、600 次/分钟**（[官方条款](https://open-meteo.com/en/terms)）。
超限会返回 `429`，且官方“保留在不事先通知的情况下封禁滥用 IP”的权利。

本集成的处理：

- `429` **不重试** —— 重试同样计入配额，只会白白消耗额度
- 配额用尽 → **逐次翻倍长退避**（30 → 60 → 120 → 240 → 480 → 720 分钟封顶），
  期间实体显示**不可用**（不拿旧数值冒充新鲜数据）
- 普通网络错误 → 10 分钟后重试；单次刷新内网络错误退避重试 3 次
- 多地点取数**全局串行**，避免同时打爆分钟级限额

> ⚠️ **若持续出现 429**：
> - 查同网络内的其它消费者（自定义 `rest` 传感器按分钟轮询的话，一个一天就是 1440 次）
> - 官方 `open_meteo` 集成每 30 分钟一轮，**每个地点每天只花 48 次**，通常不是元凶
> - **如果你的宽带是 CGNAT（运营商级 NAT，中国宽带很常见），出口 IP 是多人共享的，
>   这 10000/天 的额度也就被别人一起消耗** —— 此时降低自己用量无法解决问题
>
> 排查 CGNAT：登录路由器看 WAN 口 IP，若落在 `100.64.0.0/10` 段（RFC 6598 共享地址），即是。

### 可选：自带 API key（配额紧张时的正解）

集成选项里有 **`Open-Meteo API key`**（留空则用免费档）。填入付费档的 key 后会改走
`customer-api.open-meteo.com`——官方说明"语法与免费档完全相同，只有域名和 key 参数不同"，
而付费档**每日/每小时额度不限**（Standard 100 万次/月）。免费档的 10,000/天 是按 IP 计的，
CGNAT 环境下这一项基本无解，key 是唯一干净的出路。

> key 只存在 HA 的配置条目里，本集成不会把它写进日志。但 Open-Meteo 规定 key 走 URL 查询参数，
> 因此**如果你把 aiohttp 的日志级别开到 DEBUG**，URL（含 key）会出现在日志中 —— 别把这种日志外发。

## 已知局限

- 算法是**复刻实现**，权重与标定非官方，绝对值不可与其他产品直接比对
- 云量有"模式诊断"与"湿度廓线反演"两种口径，默认取均值（两者都放进属性供判断）
- 太阳高度角 >0 不计分（那是"金色时刻"，不是"霞"）
